RustyRig LAN/VPN beta quickstart
==============================

Keep the server on your LAN or VPN for this beta. Install matching server,
native-client and WebUI revisions: the compact rustyrig.v1 protocol has no
fallback for older releases.

1. Install or build
-------------------
For Debian packages and service setup, follow doc/INSTALLING. For a source
build on Debian/Ubuntu, fetch the checkout and install the profile reader:

XXX: default-- this is because we need it available for offline builds
XXX: of rustyrig firmware (from the pi). This might change soon!

    git clone --recurse-submodules https://github.com/PripyatAutomations/rustyrig-fw.git
    # include submodules & third party libraries we might need
    ./tools/git-pull-all.sh
    cd rustyrig-fw
    sudo apt update
    sudo apt install jq
    ./install-deps.sh

install-deps.sh PRINTS the apt command for the selected profile; run that
command with sudo to install the dependencies. Then build:

    make -j4 PROFILE=radio world

The default profile is radio. Build options live in config/radio.config.json.
For updates, use git pull followed by git submodule update --init --recursive,
then rebuild the matching components.

2. Configure a station
----------------------
Packaged server config: /etc/rustyrig/rrserver.cfg.
Edit /etc/rustyrig/rrserver.cfg after package installation. Adjust existing
settings/sections rather than adding duplicates. Start with one rig and station.name=beta:

    [general]
    station.name=beta
    rig.instances=rig0
    rig.default=rig0
    audio.test-mode=false

    [rig:rig0]
    backend=hamlib
    vfos=A B
    room=#beta-rig0
    hamlib.model=2
    hamlib.device=127.0.0.1:4532

To try this without hardware, start Hamlib's dummy rig in another terminal:

    rigctld -o -m 1

For real hardware, choose the appropriate model/device; rigctld -l lists
models. See doc/rig-rooms.md for multiple rigs and room mappings. Configure
[fwdsp] device/pipeline settings for your station's audio interface; leave
PTT off while confirming receive audio.

For Debian packages, start the service after configuring it:

    sudo systemctl enable --now rustyrig-server
    sudo journalctl -u rustyrig-server -f

3. First login
--------------
Debian fresh installations ask for the admin password through debconf. Use
that password; package upgrades preserve existing accounts and databases.

On a manual installation, a newly initialized database can provision admin with
a random password, saved beside the database in a mode-0600 file:

    /var/lib/rustyrig/db/master.db.bootstrap-password

Read it as the account running the server. Log in as admin, then change the
temporary password immediately:

    /user pass admin <new-password>

Remove the bootstrap-password file after successfully changing the password.
There is no shipped admin/admin login. Guest is disabled by default; Debian's
fresh-install prompt can enable the shared guest/guest login with RX and chat
privileges only.
Manual bootstrap leaves guest disabled. Existing
databases keep their credentials. Do not delete a database to reset a password.
Use /user list to inspect accounts and /help user for account administration.

4. Connect a client and receive audio
------------------------------------
Native client: edit /etc/rustyrig/rrclient.cfg or your home configuration.
Set the
localhost profile's credentials and disable unused profiles such as camp:

    [server:localhost]
    server.enabled=true
    server.url=ws://localhost:8420/ws/
    server.user=admin
    server.pass=<your-admin-password>

Launch the installed client with `rrclient` (or `rrclient -T` for TUI).
Keep configuration containing credentials accessible only to the owner.

The native server URL must include its scheme. Ports are optional: ws=8420,
wss=4420, irc=6667, ircs=6697. RustyRig radio/audio uses ws or wss; native IRC
is chat-only. See doc/irc-client.md for proxy and multiple-server settings.

For the browser, open http://localhost:8420/ on the server machine. Remote
browser login needs HTTPS for Web Crypto: configure net.http.tls-enabled=true
with net.http.tls-cert and net.http.tls-key, then open https://<server>:4420/.
The example config has TLS disabled; configure it before using that URL.
A VPN does not make a remote HTTP origin a browser secure context.

After login, /join #beta-rig0 attaches to the radio room. Confirm rig state,
select a codec supported by the client, and verify receive audio before TX.
Opus is a useful initial choice; native /rxcodec opus selects it. Use /help
for codec controls and doc/media-codecs.md for decoder/pipeline requirements.

5. Temporary cross-site demo access
-----------------------------------
For a multi-server demonstration, run the following on EACH destination server
to grant authenticated remote admin accounts from any linked site full rig
access, permission to join all rooms, and remote server administration:

    sudo ./tools/grant-remote-superadmin.sh 'admin@*'

The default database is /var/lib/rustyrig/db/master.db. To grant only an
account from a specific originating site, replace the wildcard:

    sudo ./tools/grant-remote-superadmin.sh 'admin@rplywv00'

For a custom database path, specify it first:

    sudo ./tools/grant-remote-superadmin.sh /path/to/master.db 'admin@rplywv00'

Quote the identity to keep * from shell expansion. Run the script from the
repository checkout on the destination host; it needs sqlite3 and database
write permission. Grants are idempotent, but are intentionally VERY broad:
they apply to present and future rigs/rooms, and site owner/admin operations.
They do not bypass RF/PTT hardware safety or replace linked-site authentication.
Do not use wildcard remote superadmin access in production.

After the demo, remove grants created by this script on EACH destination DB
(the example below uses the default path). This only removes grants bearing
the script's marker, not grants configured independently:

    sudo sqlite3 /var/lib/rustyrig/db/master.db "
      DELETE FROM privilege_set_assignments
        WHERE assigned_by='grant-remote-superadmin';
      DELETE FROM resource_privileges
        WHERE granted_by='grant-remote-superadmin';
    "

Review separately any pre-existing admin@* bootstrap grants from fresh test
database preloads: removing script-generated rows does not remove those grants.
See doc/resource-privileges.md and doc/release-checklist.md.

For reports, include the release version, frontend, selected codec, relevant
status/log messages and steps to reproduce. Redact passwords and proxy secrets.
