FETCH
-----
Pull the repo initially (this saves space and time):
     git clone https://github.com/pripyatautomations/rustyrig-fw --depth=1
     cd rustyrig-fw
     git submodule init
     git submodule update --depth=1

----	OR ----

Fetch updates & submodules
     make update


---------
CONFIGURE
---------
* Edit things in config/ as appropriate.
   # - Default profile is 'radio'
   - config/${PROFILE}.config.json has build-time config

   Edit config/rrserver.cfg to set it up
   -- SQLite is preferred; see sql/sqlite.master.preload.sql
   * SQL is preferred method of user management! *

   Source-tree databases start with the test users from the preload file.  A
   Debian server package asks for the admin password through debconf and
   applies it when creating the first database.  Existing package databases
   are preserved on upgrades.

   Once logged in as an admin or owner, use `/user list` to inspect accounts.
   `/user add`, `lock`, `unlock`, `remove`, `resetpw`, and `pass` manage
   accounts; `/user oldpw` reports passwords older than
   `security.max-pw-age` days.

Server setup below
-------------------------------------
Probably wise to use a VPN for now.

Feel free to contribute changes or improvements via github or .diff's!

Long story short, on a debian-based system do the following to try it:

   Find your rig's model # in hamlib:
	rigctld -l | less

   Start up rigctld connected to your rig (example is dummy) - the -o is important!:
	rigctld -o -m 1 &

   In rrserver.cfg (/etc/rustyrig or ./config), list the rig and select it:
        rig.instances=rig0
        rig.default=rig0
   Then configure its section:
        [rig:rig0]
        backend=hamlib
        vfos=A B
        hamlib.model=2
        hamlib.device=127.0.0.1:4532

   Multiple hamlib rigs can live on one server - list each alias in
   rig.instances, add a [rig:alias] section per rig, and set its own
   hamlib.model plus hamlib.device (an IP:port for rigctld/network, or a
   serial device path with hamlib.baud for a directly connected rig):

        rig.instances=rig0 rig1
        [rig:rig0]
        backend=hamlib
        hamlib.model=2
        hamlib.device=127.0.0.1:4532
        [rig:rig1]
        backend=hamlib
        hamlib.model=3073
        hamlib.device=/dev/ttyUSB0
        hamlib.baud=4800

   Run it with ./bin/rrserver or 'rrserver' if installed

   Open a browser and connect to the http (port 8420) or https (port 4420):
	firefox	https://localhost:4420/

You should probably use https otherwise crypto.subtle isn't available so we cant use sha1
for authentication except on localhost!


Client setup
------------
Native client rrclient has gtk and TUI (-T) modes- check it out!

Edit config/rrclient.cfg (or /etc/rustyrig/rrclient.cfg)
Run rrclient for gtk or rrclient -T (or unset $DISPLAY) for TUI.
